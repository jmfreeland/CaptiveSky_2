## 2026-10-10 — UE 5.8 Procedural Vegetation Editor (PVE)

Epic describes PVE as an experimental, PCG-based editor for authoring Nanite-ready vegetation. UE 5.8 supports three relevant workflows: grow a plant from scratch, graft structures onto a host, or import an existing vegetation mesh and extract editable PVE data. The Foliage Distributor can add foliage onto the generated plant. This is a plausible *asset authoring* route for the incoming native tree packages; it is not yet evidence that a PVE output can replace the Island's current HISM meshes or preserve their authored wind response. PVE is experimental, disabled by default, and UE 5.7 PVE assets are incompatible with 5.8. Sources: [UE 5.8 PVE guide](https://dev.epicgames.com/documentation/unreal-engine/procedural-vegetation-editor-pve-in-unreal-engine), [UE 5.8 release notes](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-5-8-release-notes).

**Native-package audit (2026-10-10):** the Fab packs are now installed under `Content/Megaplant_Library/`. UE 5.8.3's read-only commandlet loaded each species' `ProceduralVegetation`, growth-data, and grower-preset assets when PVE was enabled only for that invocation. All sixteen A-D tree variants are `SkeletalMesh`; none is a ready-made `StaticMesh` for the current HISM scatter. The PVE graph's `Graph` property is protected from Unreal Python, so this audit could not inspect its nodes or export settings. It generated no mesh and changed no project setting. Details: [native Megaplant audit](findings/2026-10-10-megaplants-native-install.md).

**Installed UE 5.8.3 export-contract audit (2026-10-18):** the local PVE headers confirm that an export can be configured as either `StaticMesh` or `SkeletalMesh`. The default is skeletal; its Dynamic Wind settings are only available on that path, while the static path explicitly has no wind simulation. PVE's export node advertises both `Mesh` and `Foliage` output (with both selected by default), and the mesh export settings expose Nanite-foliage and collision controls. This is enough to justify a *single disposable static-mesh export* as a possible bridge into the Island's existing HISM ecology; it does not prove the export is an ordinary instancable mesh, that its foliage materials survive, or that the PVE graph can be inspected/edited by Python. Do not alter or replace the installed skeletal assets. Once the main-project editor is responsive, export one low-risk variant to a new disposable path with collision disabled, verify the resulting asset class/material slots/Nanite and bounds, then run one matched Tideglass-to-Woodland Game view and profile it against the existing foliage. Only proceed to a sparse HISM trial if the silhouette and materials read well and the run stays above the 30-FPS floor. If static export loses essential wind, separately validate the existing instanced-skinned path and transform-provider data; do not assume PVE's skeletal wind preset makes it performant. Local evidence: `PVExportParams.h`, `PVExportSettings.h`, `PVData.h`, and `PVExporter.h` in the UE 5.8.3 installation. Exporter implementation is not present in the installed plugin source, and the current editor is nonresponsive, so no asset was generated or tested in this audit.

**Current direction (2026-10-13; supersedes the PlantFactory setup notes below):** the deprecated content-only mount is retired from the active project. Its original plugin folder and the four disposable migration-trial materials are preserved outside `Content/` in `Saved/Backups/PlantFactoryRetired_20261013/`. The main project descriptor no longer names the mount. The two material functions still needed by the Island were migrated to `/Game/Generated/PlantMaterialCompatibility`; the post-migration audit found no `/Game` referencers to the original plugin assets. Keep those project-local compatibility functions and the migrated foliage materials. PVE is a separate UE 5.8 authoring tool and remains enabled. Its next test should use the PVE editor export UI on a disposable graph/output once Unreal startup is stable; do not re-enable PlantFactory or scatter the current Beech output, whose silhouette and material remain unsuitable.

PCG may separately help art-direct repeatable Tideglass-to-Wind-Arch habitat bands using the project's species, landscape awareness, and landmark exclusions. Treat that as an editor-authored composition experiment, not as the source of truth for resident-made changes: persistent world modifications should continue to flow from canonical world-state records, not untracked baked PCG output. PCG's Static Mesh Spawner can place weighted mesh variants, while its GPU procedural instancing path is explicitly experimental and lacks persisted instances, collision, navigation, ray-tracing, and distance-field support; it is not a drop-in replacement for the current runtime HISM ecology. Sources: [PCG overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/procedural-content-generation-framework-in-unreal-engine), [GPU processing limitations](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-pcg-with-gpu-processing-in-unreal-engine).

**Effort/risk:** medium for a one-species PVE proof; high to adopt it broadly because it is experimental and needs separate fidelity, wind, runtime, and performance validation. The installed Beech preview already shows that enabling foliage rendering and adjusting tint do not by themselves produce a usable canopy; use another species or a complete authored output only after judging its full silhouette in Island composition.
