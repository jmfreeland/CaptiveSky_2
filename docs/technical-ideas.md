## 2026-10-10 — UE 5.8 Procedural Vegetation Editor (PVE)

Epic describes PVE as an experimental, PCG-based editor for authoring Nanite-ready vegetation. UE 5.8 supports three relevant workflows: grow a plant from scratch, graft structures onto a host, or import an existing vegetation mesh and extract editable PVE data. The Foliage Distributor can add foliage onto the generated plant. This is a plausible *asset authoring* route for the incoming native tree packages; it is not yet evidence that a PVE output can replace the Island's current HISM meshes or preserve their authored wind response. PVE is experimental, disabled by default, and UE 5.7 PVE assets are incompatible with 5.8. Sources: [UE 5.8 PVE guide](https://dev.epicgames.com/documentation/unreal-engine/procedural-vegetation-editor-pve-in-unreal-engine), [UE 5.8 release notes](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-5-8-release-notes).

**Native-package audit (2026-10-10):** the Fab packs are now installed under `Content/Megaplant_Library/`. UE 5.8.3's read-only commandlet loaded each species' `ProceduralVegetation`, growth-data, and grower-preset assets when PVE was enabled only for that invocation. All sixteen A-D tree variants are `SkeletalMesh`; none is a ready-made `StaticMesh` for the current HISM scatter. The PVE graph's `Graph` property is protected from Unreal Python, so this audit could not inspect its nodes or export settings. It generated no mesh and changed no project setting. Details: [native Megaplant audit](findings/2026-10-10-megaplants-native-install.md).

**Next experiment:** after the open editor is saved and the user approves the required restart, enable the experimental PVE plugin in the project and inspect one installed species graph in the editor. Export one candidate into a disposable preview folder, then compare silhouette, scale, material slots, wind, Nanite/static-versus-skeletal output, and acceptance by the existing HISM scatter path. Use the fixed Tideglass-to-Wind-Arch camera and capped Game profile to compare frame time; don't assume Nanite or generated foliage improves performance. Keep the original package and all USD sources. Only adopt the generated asset after fidelity and runtime checks pass; if it does not preserve the needed material/wind behavior or HISM compatibility, discard the experiment and use the native package without converting it.

PCG may separately help art-direct repeatable Tideglass-to-Wind-Arch habitat bands using the project's species, landscape awareness, and landmark exclusions. Treat that as an editor-authored composition experiment, not as the source of truth for resident-made changes: persistent world modifications should continue to flow from canonical world-state records, not untracked baked PCG output. PCG's Static Mesh Spawner can place weighted mesh variants, while its GPU procedural instancing path is explicitly experimental and lacks persisted instances, collision, navigation, ray-tracing, and distance-field support; it is not a drop-in replacement for the current runtime HISM ecology. Sources: [PCG overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/procedural-content-generation-framework-in-unreal-engine), [GPU processing limitations](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-pcg-with-gpu-processing-in-unreal-engine).

**Effort/risk:** medium for a one-species disposable proof; high to adopt PVE broadly because it is experimental, adds plugin/content dependencies, and needs separate fidelity, runtime, and performance validation. No plugin, project setting, level, or Content asset was changed for this evaluation.
