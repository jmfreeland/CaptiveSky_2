# Night sky visibility probe (2026-10-03)

The earlier Day 1, 00:00 Tideglass capture was a new-moon state and its camera faced away from the Moon, so it did not prove that the lunar disk was missing. A dedicated Day 15, 00:00 UE 5.8.3 D3D12 SceneCapture pointed toward the zenith and confirmed the full-moon disk renders through the cloud layer. The `CaptiveSky2.Visual.Viewpoints` test passed for that probe. The capture is [here](../../Saved/CompileScratch/Codex_UnderstoryVerify_20261002/Project/Saved/Viewpoints/2026-10-03_141827_h00.0/06_MoonZenithProbe.png); the log is [here](../../Saved/Logs/Codex_MoonZenithProbe_Day15_20261003.log). The temporary probe camera was added only to the disposable scratch project's `Config/IslandViewpoints.json` and then removed; the main map and user-edited viewpoint config were not changed.

The level's `IslandDayNight.Moon` uses `bAtmosphereSunLight=true`, light index 1, and an atmosphere disk color scale of white. Its missing appearance in the Tideglass frame was a framing issue, not a broken moon-light configuration.

The first runtime starfield prototype now layers over the existing SkyAtmosphere without replacing the cloud look or touching shared `Content/`. It creates 1,200 deterministic, emissive, depth-tested quad stars in six visibility groups on a 20 km shell. Groups emerge progressively as the sun descends through twilight and clouds naturally obscure them. The full-moon zenith capture with the starfield is [here](../../Saved/CompileScratch/Codex_UnderstoryVerify_20261002/Project/Saved/Viewpoints/2026-10-03_150356_h00.0/06_StarsZenithProbe.png); the [capture log](../../Saved/Logs/Codex_Starfield_Zenith_Day15_20261003.log) passed `CaptiveSky2.Visual.Viewpoints` and recorded a 39.38 FPS startup gate. The focused [clock test log](../../Saved/Logs/Codex_Starfield_DuskTest_20261003.log) passed both `CaptiveSky2.Agent.DayNight` and `DayNightPersistence`, including assertions for no stars at noon, staged visibility at dusk, and all groups visible at midnight.

This is still a prototype: it uses Unreal's built-in `VertexColorMaterial` as an emissive vertex-color material. Validate that dependency in a packaged/cooked build before treating it as shippable; if it is not retained there, replace it with a project-owned material after coordinating on `Content/` ownership.

The 30 FPS minimum remains enforced for gameplay-scale captures and is the acceptance floor, not a stretch goal. A separate Tideglass capture reported 18.34 FPS while the main editor was also open; that concurrent run is not a clean performance baseline and does not justify lowering the floor. Re-run the gameplay-scale check only when the main editor is idle, and do not infer packaged or target-hardware performance from SceneCapture throughput.
