# Resident proposal memory (2026-10-11)

When a resident successfully adds an object or upgrade idea to the existing human-review queue, the controller now records a durable observation for that resident. It includes the submitted description, target and upgrade category where applicable, and the queue's stable proposal ID. The wording explicitly says the proposal is pending review and nothing has yet been created or placed. Duplicate or invalid requests do not create memories; the queue remains the source of truth for whether a proposal was actually recorded.

This is an action result, not an extra thought or model request. It does not approve the proposal, invoke the asset pipeline, or mutate the Island. The focused `CaptiveSky2.Agent.IslandProposalMemory` automation test covers object and upgrade successes, duplicate rejection, invalid input, and memory tags. The fixture uses the project's autonomous placeholder body with its concrete Raven controller; it calls the controller's `HandleDecisionReady` directly because the headless fixture's decision multicast did not reach the controller action. Therefore this test verifies request-to-memory behavior, not multicast delegate dispatch.

The first live-editor run exposed that the old fixture tried to spawn abstract `AAutonomousAgentAIController`. After correcting the controller fixture, the isolated scratch target built successfully in 31 actions, and the focused test passed under UE 5.8.3 with `NullRHI`, `-CaptiveSkyDisableAgentThinking`, and `-CaptiveSkyMaxModelRequests=0`. `-DDC-ForceMemoryCache` was required because the sandbox could not read the user's Installed DDC test file. The log is [`ProposalMemoryFixtureFix_DirectHandler.log`](../../Saved/CompileScratch/Codex_WildlifeHomeRecord_20261011/Saved/Logs/ProposalMemoryFixtureFix_DirectHandler.log). The Island map and main-project binaries were not changed; full dynamic-delegate dispatch and an in-world resident run remain separate validation gates.

A follow-up fixture began the transient world before possessing the resident and confirmed `OnDecisionReady.IsAlreadyBound(Controller, &AAutonomousAgentAIController::HandleDecisionReady)`, but broadcasting a valid object request still did not enter action handling or record memory. The automation log is `Saved/Logs/ProposalMemoryBroadcast_Verbose.log`; it records the expected failures and the controller's Raven `OnPossess` appearance log, but no `LogAutonomousAgentAI` handler message. This leaves an unresolved discrepancy between the dynamic delegate's binding list and its runtime invocation in this headless setup. The test source was restored to the previously passing direct-handler form; do not treat this experiment as a passing dispatch test.
