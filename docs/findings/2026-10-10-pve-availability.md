# Procedural Vegetation Editor availability (2026-10-10)

UE 5.8.3 includes the Experimental `ProceduralVegetationEditor` plugin at `Engine/Plugins/Experimental/ProceduralVegetationEditor`. Its descriptor is marked `IsExperimentalVersion: true` and `EnabledByDefault: false`. `CaptiveSky_2.uproject` opts in, and a later read of the live editor confirms it is enabled there now.

To check compatibility first, I enabled the plugin in the ignored isolated scratch descriptor at `Saved/CompileScratch/RatAnimationProbe_20261010/CaptiveSky_2.uproject`. The installed engine mounted `ProceduralVegetationEditor` and loaded both `UnrealEditor-ProceduralVegetation.dll` and `UnrealEditor-ProceduralVegetationEditor.dll`. UBT accepted the PVE-enabled project configuration, and the scratch editor completed the existing `CaptiveSky2.Agent.RatLocomotionAnimation` test under `NullRHI`, disabled resident thinking, zero model requests, and a 60-second cap ([log](../../Saved/CompileScratch/RatAnimationProbe_20261010/PVEAvailability.log)). After that compatibility check, I added the same plugin enablement to the main `.uproject`. At the time, the open editor had not yet been restarted. A subsequent live Unreal MCP read now reports `ProceduralVegetationEditor` enabled, and the current session log confirms it mounted and loaded both editor/runtime modules. The same live read found no `/PlantFactoryPlugin/` content mount, although that content-only plugin exists at `Plugins/PlantFactoryPlugin/` and was successfully mounted in the scratch probe. I have now explicitly enabled `PlantFactoryPlugin` in the main project descriptor for the next launch; this is not yet verified in the running session. No Content or live level state was changed.

This proves the installed 5.8.3 PVE plugin can load in a scratch copy and the current main editor; it does not prove interactive vegetation authoring, generated asset quality, Nanite suitability, compatibility with the existing Fab Megaplants, or runtime performance. After a normal project restart, first confirm `/PlantFactoryPlugin/` is mounted and the Megaplant materials resolve; then inspect one installed species graph and, if its authoring flow is viable, export one small woodland-edge candidate into a disposable preview before any Island placement.

The first PVE probe lacked the project-local `Plugins/PlantFactoryPlugin` directory and therefore reported its material-function references missing. I corrected the scratch setup with a junction to the main project's content-only plugin (no assets copied or modified) and reran startup. `PVEPlantSupportProbe.log` now confirms both `ProceduralVegetationEditor` and `PlantFactoryPlugin` mount, the PVE editor module loads, the plant packages scan without `LoadErrors`, and `CaptiveSky2.Agent.RatLocomotionAnimation` passes. This validates plugin discovery and package-mount compatibility in the isolated scratch project; it does not validate interactive PVE authoring or rendered/runtime behavior in the live project.
